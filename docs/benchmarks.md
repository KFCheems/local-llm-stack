# 实测数据（RX 7900 XT 20GB / 9800X3D / 32GB RAM / llama.cpp Vulkan b11212）

以下全部为本机实测，非推测。供同类硬件做容量规划参考。

## 1. 上下文容量与速度悬崖（27B 稠密 IQ4_XS，权重 14.3GB）

KV 每 token 占用（GPU 显存差值法实测）：

| KV 量化 | 每 token | 32K 全套 VRAM |
|---|---|---|
| q8_0 | ~36 KB | 15.9 GB |
| q4_0 | ~19.5 KB | 15.8 GB |

逐档实测（q4_0 KV，-fa on，128 token 生成）：

| 上下文 | VRAM | 解码速度 | 预填充 |
|---|---|---|---|
| 32K | ~16.6 GB | 35 tok/s | ~670 tok/s |
| 128K | 18.14 GB | **35.3 tok/s（全速）** | 137 tok/s |
| 160K | 18.73 GB | **35.3 tok/s（全速）** | 135 tok/s |
| 176K | 18.73 GB | **12.1 tok/s** ❌ | 64 tok/s |
| 192K | 19.01 GB | **11.9 tok/s** ❌ | 63 tok/s |

**结论**：176K 处存在算子分档悬崖（不是显存不足——176K 与 160K 显存相同），
Vulkan 后端注意力内核在该 KV 规模切换到慢速路径。20GB 卡 + 27B 稠密的
最优点就是 **160K**。算账公式：
`VRAM ≈ 权重 + 1.8GB 运行时 + 上下文 × 每token KV`，但**必须实测档位**。

（旁证：35B-A3B MoE 在同卡标称 256K 上下文，但其前端的压缩代理实际只让
有效上下文用到 32K —— 标称窗口 ≠ 可用窗口。）

## 2. 投机解码 A/B（27B 稠密，全 GPU）

| 方案 | 解码速度 | 备注 |
|---|---|---|
| 基线 | ~35 tok/s | |
| MTP 官方草稿（1.37GB，接受率 ~50%） | **9.7 tok/s** ❌ | 验证批次吃掉带宽收益 |
| ngram 投机（零成本） | ~37 tok/s | 一般文本无增益 |

MTP 投机适合"权重在内存/磁盘调页"的 MoE 场景（实测在调页型 131B 上是
3.9 tok/s，更糟）；全 GPU 稠密模型上结论一致：**别开**。

## 3. 子代理"手"选型横向对比

两个候选（同为稠密 27B、同卡、同参数 max_output_tokens=2000、同链路），
6 项子代理典型任务：

| 任务 | 候选 A（Cyber 特化） | 候选 B（官方 27B 去审查） |
|---|---|---|
| T1 代码生成（均衡切分） | **FAIL**：思考失控烧满 2000 token，正文截断 | PASS，一发完整正确 |
| T2 代码修改（去重 bug） | PASS（1024 tok） | PASS（**283 tok，省 3.6 倍**）|
| T3 工具调用 | PASS | PASS |
| T4 指令遵循（逐字输出） | PASS | PASS |
| T5 中文理解 | PASS | PASS |
| T6 综合重构（列表推导） | PASS | PASS |

**结论**：速度相同（同为带宽极限），可靠性和思考开销才是子代理选型的决定因素。
选"手"时优先测 T1（生成可靠性）和 T2 的 token 效率。

## 4. 引擎与槽位管理实测

- 按需启动：热页缓存 10-25 秒 ready；真冷（WSL 重启后）1-4 分钟
- 闲置自停：整 300 秒准时停止（进程级），显存立即释放
- 互斥：A 槽占卡时 B 槽启动被拒，503 指名道姓；等 A 闲置自停后 B 可用
- 两个稠密 27B 全力档：14.3-14.6GB 权重 → 引擎运行时 18.1-18.7GB（160K KV）

## 5. 公网链路（Cloudflare Tunnel）

| 指标 | QUIC（默认） | http2（切换后） |
|---|---|---|
| 首请求 TTFB | 25.7s ❌ | 1.36s ✓ |
| 稳定态每请求开销 | 偶发抽风 | 稳定 0.6-1.5s |

大陆家宽到 CF 边缘 RTT ≈ 250-300ms 是物理下限；对 LLM 推理占比不大。
冷启动场景由 shim 的 SSE 心跳（15s 间隔注释行）保活，不会被边缘
100 秒空闲超时掐断。
